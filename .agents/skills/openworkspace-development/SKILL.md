# OpenWorkspace development

Follow [the development guide](../../../AGENTS.md) for canonical commands, safety and knowledge ownership. Read [the roadmap](../../../ROADMAP.md) only for the affected decision or scope. Do not replay the whole roadmap or pull in later scope implicitly.

## Preflight

Identify the changed boundary: dispatch/flags, wait/ownership, redaction, supervision lifecycle, or skill packs. Read its actual implementation and nearest tests. Record allowed files and existing runtime ownership in the session. An application checkout under test is read-only data, never an edit target.

## Development loop

1. Define the smallest observable acceptance scenario and its denial/preservation case.
2. Implement the bounded change. Keep an existing implementation owner through edit/test/fix. Use specialized guidance only for the affected surface; a skill does not expand the role's authority.
3. Run the affected native checks from `AGENTS.md` (`bun test cli/`). Reuse unchanged PASS evidence. A passing handler unit test is insufficient for changed dispatch, flags, or wait behavior.
4. At the behavior boundary, exercise the actual binary built from the changed source as described below. Report observed results and unimplemented boundaries separately.
5. A milestone lands only on evidence pulled from a real run, never on implementation claims — record the evidence with the change or it didn't happen.

## Actual interface checks

**CLI verbs (read-only, redaction, containment):** prove a read-only verb by execution trace (no write/spawn on the path) plus a byte-identity check on the artifacts it claims not to touch. Compose summaries only from existing readers; a new collector inside a rendering verb re-opens the secret boundary. The redaction order is fixed — secret mask → absolute-path fold → short-8 for revs/digests → fence neutralization — and the whitespace-token masker never runs over compact JSON: parse first, walk values, re-stringify (wrong order silently corrupts structure while still exiting 0). Fenced blocks are always valid JSON or absent — an absent section emits a plain line, never a fenced `json` wrapper around placeholder text. File-writing flags validate the target before any tmp creation, refuse `.`/empty/directory/symlinked-parent targets through realpath containment, and echo basenames only. A flag accepted by one verb exits 2 on every other verb — never a silent no-op that still performs the action (seen: `down --bundle` executed stop).

**Verb dispatch and landed-state contracts:** every `COMMANDS` entry needs a dispatch test that reaches its own handler with its claimed output shape; a documented verb that falls through to a sibling is a high-severity defect. When a milestone lands, sweep its "pending"/"not yet supported" claims out of docs, help text and refusal strings in the same change. Refusal tests assert the contract marker plus a positive control — a bare exit-code assertion stays green under broken routing.

**Process ownership:** a listener on a forked child still belongs to the recorded launcher — prove descent (ppid chain + `lstart` match, bounded hops, cycle-safe) before calling a port foreign or a pid stale; an unprovable claim stays a legacy exact-match, never an ownership verdict. Never kill a holder on an UNVERIFIED claim (seen: mvn/node-style `sh -c '… & wait'` flagged `foreign-port`).

**Identity before compare:** compare build/digest identity (sidecar vs recorded vs live) before concluding staleness; shorts on the wire, full digests never in output.

**Doc==code for flags:** every documented flag/token is grepped against `--help` and its emitter; a flag accepted by one verb exits 2 on every other verb — fail-loud, never a silent no-op that still performs the action.

**Skill packs:** `skills/` is the only hand-edited skill text; `plugins/` mirrors are generated by `pnpm build-skill-packs` and byte-compare tested. A claimed skill change without regenerated mirrors is a defect, not a shortcut.

## Recovery and result

Classify CLI vs harness failure before retrying. Change the relevant condition or hypothesis; never weaken an assertion, bypass confirmation, alter an application's toolchain or reinstall global tools just to obtain PASS. Stop if the next action needs a real credential/provider, shared mutation or changed product/security contract outside scope.

Return changed files, actual checks/results, the environment and real/fake boundary, concrete CLI observations and remaining failures. No separate evidence.md is required. Save a repeatable rule in its existing owner; make a regression test for a demonstrated repeated failure when practical.

## Cleanup

Delete owned fixtures only after the check that needs them. Stop only task-owned disposable services; retain an explicitly handed-over artifact. Do not retain browser storage or HAR captures as test artifacts. Never stop a foreign port holder to free a port.

## Shell-log flake diagnosis (dev-only)

Join the opencode shell-observer log at `~/.local/share/opencode-shell-log/shell-events.jsonl` with run summaries by timestamp and workdir. Grep for `exit!=0` lines, duration outliers, and retry shapes (repeated identical commands). Join rule: match a verification run's timestamp within a small window and the same workdir. Honesty note: correlation is not causation, and an empty log proves nothing — the run may have bypassed the observer or never shelled out.
