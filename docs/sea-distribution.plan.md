# SEA Distribution (Node-free single binary) - Implementation Contract

## Problem and Success Criteria
- A user on macOS arm64 (first) or Linux x86_64 (second) with no Node.js/pnpm installed downloads one file, runs one command (`./openworkspace start`), and gets the identical product: loopback service on 4318, dashboard opens, first-run project registration works, MCP bridge connects an external assistant.
- Success = fresh-machine matrix green: start → `/health` ready → dashboard HTML + hashed asset → `/api/client-config` pointing at the binary → MCP `tools/list` → `workspace_register` + `workspace_inspect` on a fixture, with 0600/0700 state and no token leakage — all with no `node`/`pnpm` resolvable in PATH.

## Decisions
- **Build tool: Node.js SEA via `node --experimental-sea-config` + postject injection** (contract verified against Node v22.23.3 docs — the pinned major; see plan-authoring rule in Final Validation). Steps: version-matched downloaded Node 22 binary generates `sea-prep.blob` → `cp` target node → macOS only: `codesign --remove-signature` first → postject `NODE_SEA_BLOB` (`--macho-segment-name NODE_SEA` on macOS, ELF note / default on Linux) with `--sentinel-fuse NODE_SEA_FUSE_fce680ab2cc467b6e072b8b5df1996b2` → macOS: `codesign --sign -` after. No `mainFormat` field (no such Node 22 field — injected main is CommonJS-only), no `--build-sea` (v25.5.0+, absent on 22). No pkg/nexe/caxa: SEA is first-party, no new dependency. Base stays Node 22 LTS because it is the declared runtime floor and the ecosystem lockfile target — not 26.
- **Embedded runtime: official Node.js 22 LTS binary per target, pinned ≥22.20.0** (exact patch pinned + SHASUMS-verified at implementation time; ≥22.20.0 required because `sea.getAssetKeys()` — used by the M1 gate — was added in v22.20.0). The downloaded binary both runs `--experimental-sea-config` and is the postject injection target (blob-gen and injection-target versions must match exactly). `useSnapshot: false`, `useCodeCache: false` (Node 22 cross-build rule: caches/snapshots crash when built on a different platform; also `import()` is broken under `useCodeCache: true`; startup speed is irrelevant for a long-lived service).
- **One bundle, one binary, argv dispatch — via MANDATORY `runService()`/`runMcpBridge()` extraction (primary path, not fallback).** esbuild cannot bundle top-level await into CJS, and the real graph is full of it (`src/main.ts:10`, `src/mcp.ts:16,22,27,347,358`, `src/consumer-skills.ts:109`). So: extract the top-level bodies into exported `runService()` (main.ts) and `runMcpBridge()` (mcp.ts) with behavior-preserving TLA-free dual-entry guards (each file still runs its runner under tsx when invoked directly, and does nothing on plain import — the guard compares `process.argv[1]` by filename suffix WITHOUT `fileURLToPath(import.meta.url)`, which is undefined under CJS). New `src/sea-entry.ts` (CJS) parses argv and calls exactly one runner — only the dispatched runner executes, asserted in every gate (see E1/M1/M2).
- **Consumer-skills TLA fix is two-sided (G1): `src/workspace.ts:19` statically imports `availableSkills` and `onboarding()` returns it synchronously at `:451`, so merely deleting the await in `consumer-skills.ts` would leave onboarding serving an empty list (regression caught by `test/mcp.test.ts:153-165`, which asserts plan skills equal on-disk skills).** Fix: `consumer-skills.ts` exports **mutable live bindings** (`availableSkills`, and `consumerSkills` if still re-exported) populated by an exported `initConsumerSkills()` (or equivalent), invoked from **BOTH** `runService()` and `runMcpBridge()` before serving — the `workspace.ts` live import then stays populated under tsx entries, the SEA service entry, and the SEA MCP entry alike. `src/workspace.ts` itself is in scope for the import-shape change if the implementer needs it (no behavior change to `onboarding()` output).
- **REQUIRED `import.meta.url` packaging fix (not additive).** esbuild CJS empties `import.meta.url`, which crashes module-load-time evaluation at `src/static-assets.ts:32` (`defaultAssetRoot`) and `src/consumer-skills.ts:5` (`defaultSkillsDirectory`). Fix via explicit esbuild `--define` shim or lazy/guarded computation (compute inside functions, guarded by `sea.isSea()` so the SEA path never evaluates the filesystem default; source path computes exactly as today). `src/http.ts:425` is handler-safe only if the SEA branch precedes the `fileURLToPath(.../bin/openworkspace.mjs)` evaluation — order the branch first. All three sites documented in M1 subphase 3 as required changes.
- **Asset story: `sea.getAsset()` with explicit build-time enumeration, NOT `useVfs`.** Rationale: `getAsset` stable since v20.12 (inside the 22 floor); `useVfs` does not exist on Node 22. Build script enumerates `web-dist/**` into the sea-config `assets` dict as `web-dist/<rel>` keys **plus `skills/*/SKILL.md` as `skills/<name>/SKILL.md` keys** (4 dirs observed: `browser-qa`, `learn-from-mistake`, `scaffold-local-tool`, `openworkspace-onboarding` — without this the SEA binary silently drops all MCP prompts/onboarding skills). `loadStaticAssets` gains an `isSea()` branch that reads bytes via `getAsset` but runs the **unchanged** manifest/hash/HTML validation; `loadConsumerSkills` gains an `isSea()` reader (enumerate via `getAssetKeys()` filter + same frontmatter/size validation). Symlink/`O_NOFOLLOW`/`lstat` filesystem proofs are vacuous-but-unreproducible inside the read-only blob; the hash allowlist (assets) and frontmatter/size checks (skills) remain the enforcement. Invariant "MCP tool/prompt surface unchanged" is gated by a `tools/list` + skill-prompt fetch assertion in the matrix.
- **SEA entry replicates the companion CLI contract exactly** (`start [--state-directory ABSOLUTE] [--port N] [--no-open]`, `mcp [--state-directory ABSOLUTE]`, same error strings). `bin/openworkspace.mjs` stays untouched for source preview.
- **`/api/client-config` branches on `sea.isSea()`**: SEA → `{command: process.execPath, args: ['mcp','--state-directory', dir], env: {OPENWORKSPACE_HOME: dir}, sea: true}`; source → current shape unchanged. The additive `sea: true` flag (SEA responses only) is the UI signal that switches the dashboard copy-setup text off its stale "requires the existing OpenWorkspace Node runtime … not a Node-free installer" sentence (`frontend/src/features/ai-setup/format-setup.ts:162`) to the binary path. This restates (not reuses) the PATH-independent launch: inside SEA there is no checkout, no `node_modules/tsx`, and `process.execPath` IS the product.
- **`execArgvExtension: "none"`** (supported on Node 22). "none" closes a `NODE_OPTIONS` preload-injection vector in the shipped binary, consistent with the minimal-env opener policy (repo tests keep using `NODE_OPTIONS` against source only).
- **`disableExperimentalSEAWarning: true` (cosmetic only — suppresses the console warning, not a stability claim). Node rates SEA stability 1.1 "Active development": the README distribution section and the Risks section must state the experimental status honestly.**
- **Signing: ad-hoc `codesign --sign -` after injection on darwin (with `codesign --remove-signature` before injection); plain `chmod +x` on Linux. No notarization, no Developer ID in v1** (non-goal; download path documents `xattr -d com.apple.quarantine <binary>` as the primary bare-CLI clearance step, right-click-open as the alternative).
- **State/home: unchanged.** `OPENWORKSPACE_HOME` default (`~/.local/share/openworkspace`), 0700/0600 enforcement, fail-closed schema, single-service lock — same code, new shell. No portable-home mode in v1.
- **NOT bundled (system-resolved, honest-unavailable preserved):** `psql`, `pm2`, `agent-browser`, `/usr/bin/osascript` (darwin-only picker; headless/manual fallback on Linux unchanged), `/usr/bin/open` + `xdg-open` (dashboard opener unchanged). No behavior change in `trusted-system.ts`, `local-tools.ts`, `services.ts`.
- **Update story: explicitly out of v1.** No auto-updater, no version check, no `--version` addition. Update = re-download. (If the implementer finds version stamping is free via existing `package.json` version string, it may surface it in `--help` output only — no new flag contract.)

## Scope
- Allowed: new `src/sea-entry.ts` (CJS), new `scripts/build-sea.mjs` + generated sea-config/blob (gitignored artifacts) + postject step (**exact postject version pinned in the build script — reproducible supply chain, no floating `npx postject`**), behavior-preserving `runService()`/`runMcpBridge()` extraction in `src/main.ts` + `src/mcp.ts` with TLA-free dual-entry guards (tsx entries call the same functions), REQUIRED `import.meta.url` load-time fix at `src/static-assets.ts:32` + `src/consumer-skills.ts:5` (shim or lazy/guarded) with SEA-branch-first ordering at `src/http.ts:425`, `isSea()` readers in `src/static-assets.ts` + `src/consumer-skills.ts` (mutable live bindings + `initConsumerSkills()` called from both runners) + `src/http.ts` (client-config SEA shape incl. `sea: true`), `src/workspace.ts` import-shape accommodation if needed (no `onboarding()` output change), `skills/**` as SEA asset keys, optional `sea?: boolean` on frontend `ClientConfig` (`frontend/src/api.ts:230-232`, fixtures e.g. `workbench.test.tsx:8` updated — source responses omit the flag) + copy-text-only branch in `frontend/src/features/ai-setup/format-setup.ts` (SEA flag on / source sentence off), new `test/sea-*.test.ts` **plus a source-mode client-config shape test that lands BEFORE the branch**, `dist/` output (gitignored), README distribution section (with experimental-status note), ROADMAP progress line.
- Forbidden: changes to registration/schema/lock/permissions/auth/CSP/opener/discovery/verification behavior; new runtime features; Windows support; DMG/pkg; notarization; auto-update; removing or altering `bin/openworkspace.mjs` source-preview path; committing binaries/blobs.

## Risks and Rollback
- Risk: Node SEA is stability 1.1 "Active development" — future Node majors may change the blob/postject flow → mitigation: pin Node 22 ≥22.20.0 as the base, document experimental status in README, keep the source-preview path fully working so packaging can be re-cut. Rollback: distribution is additive — delete `dist/`, revert extraction/shim/readers, source preview unaffected.
- Risk: Gatekeeper quarantine blocks double-click on ad-hoc-signed binary → mitigation: document `xattr -d com.apple.quarantine <binary>` as the primary bare-CLI clearance (right-click-open alternative); notarization stays a future product decision, not a silent scope add. Rollback: as above.
- Risk: esbuild bundling breaks on the real TLA graph or an MCP SDK dynamic import → mitigation: E1 bundles the real graph first; bundle smoke includes MCP `tools/list` + skill prompts. Rollback: same as above.
- Risk: Linux cross-build fails → mitigation: E2 fallback to native build; never ship an unexecuted Linux binary as supported.
- Rollback for all milestones: remove `dist/`, build script, new tests, extraction/shim/readers/flag; no state migration involved (state format untouched).
